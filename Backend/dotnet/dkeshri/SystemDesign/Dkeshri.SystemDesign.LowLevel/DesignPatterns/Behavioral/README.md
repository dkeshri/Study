# Behavioral Design Patterns

Behavioral patterns describe how objects communicate and distribute responsibility.

## Chain of Responsibility

Passes a request through a sequence of handlers until one handles it. [More information](https://refactoring.guru/design-patterns/chain-of-responsibility).

## Command

Encapsulates a request as an object so it can be queued, logged, or undone. [More information](https://refactoring.guru/design-patterns/command).

## Iterator

Provides a way to traverse a collection without exposing how it stores its elements. [More information](https://refactoring.guru/design-patterns/iterator).

## Mediator

Centralizes communication between related objects to reduce their direct dependencies. [More information](https://refactoring.guru/design-patterns/mediator).

## Memento

Captures and restores an object's previous state without exposing its internal details. [More information](https://refactoring.guru/design-patterns/memento).

## Observer

Notifies subscribed objects automatically when another object's state changes. [More information](https://refactoring.guru/design-patterns/observer).

## State

Allows an object to change its behavior when its internal state changes. [More information](https://refactoring.guru/design-patterns/state).

## Strategy

Defines interchangeable algorithms and lets a client select one at runtime. [More information](https://refactoring.guru/design-patterns/strategy).

## Template Method

Defines the skeleton of an algorithm while letting subclasses customize selected steps. [More information](https://refactoring.guru/design-patterns/template-method).

## Visitor

Adds operations to a group of object types without changing those types. [More information](https://refactoring.guru/design-patterns/visitor).
