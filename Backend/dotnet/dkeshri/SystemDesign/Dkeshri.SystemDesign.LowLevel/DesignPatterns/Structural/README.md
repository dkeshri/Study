# Structural Design Patterns

Structural patterns describe how classes and objects are composed into larger structures.

## Adapter

Allows otherwise incompatible interfaces to work together through a wrapper. [More information](https://refactoring.guru/design-patterns/adapter).

## Bridge

Separates an abstraction from its implementation so both can vary independently. [More information](https://refactoring.guru/design-patterns/bridge).

## Composite

Composes objects into tree structures so individual objects and groups can be treated uniformly. [More information](https://refactoring.guru/design-patterns/composite).

## Decorator

Adds behavior to an object dynamically by wrapping it with another object. [More information](https://refactoring.guru/design-patterns/decorator).

## Facade

Provides a simpler interface to a complex subsystem. [More information](https://refactoring.guru/design-patterns/facade).

## Flyweight

Shares common state between many objects to reduce memory use. [More information](https://refactoring.guru/design-patterns/flyweight).

## Proxy

Provides a substitute object that controls access to another object. [More information](https://refactoring.guru/design-patterns/proxy).
